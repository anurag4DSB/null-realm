We have a RING deployment with separated Data and Management networks, and
a customer is about to configure S3C on top of it. In their inventory they
are only setting `ansible_host` for each node (pointing at the management
IP) and haven't set `data_host`. Before they run the deployment, the
question came up: are the S3 services network-agnostic — will they listen
on all interfaces and let traffic land on whichever network the client
uses — or will omitting `data_host` end up pinning S3C to the management
network? Need a definitive answer and, if it's the latter, enough evidence
from the playbooks to convince the customer to set `data_host` up front.

EXPECTED ANSWER OUTLINE:
Services are not network-agnostic by default. Despite binding on 0.0.0.0,
every cross-host address is advertised via a single variable that
silently falls back to the management IP when `data_host` is unset. The
pattern propagates through essentially every stateful and stateless role
that exposes a peer-facing endpoint. The customer should set `data_host`
on every inventory host before deploying; retrofitting requires
re-templating and restarting most roles.
